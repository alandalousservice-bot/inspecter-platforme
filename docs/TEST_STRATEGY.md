## TASK-052A — Inspector professional identity

Migration clean+upgrade مع Inspector rows قائمة: الحقلان NULL دون backfill، pair CHECK، وعدم كسر IDs والجلسات/ACTIVE/INACTIVE/العضويات/login. GET/PUT ذاتيان فقط، CSRF/no-store، Unicode عربي/غير عربي، NFC/trim/فراغات وحد 100 code points، رفض control/blank/null/unknown keys، AuditLog واحد لأسماء الحقول المتغيرة فقط داخل transaction، no-op بلا audit. UI RTL/keyboard/loading/error/success وconnected browser لإكمال الاسم واللقب؛ لا تحرير Inspector آخر أو كشف البريد كاسم عرض. شغّل regressions auth/API/DB وtypecheck/lint/tests/build/diff-check.

## TASK-052 — Pedagogical accompaniment report

DB: migration واحدة forward-only بعد TASK-052A، clean chain وترقية من HEAD بلا backfill؛ `visitId` unique، FK Restrict، status/revision/provenance/حدود النصوص وCHECK النهائي/المسودة واللقطات. API: scope ACTIVE Inspector + عضوية District الحالية + ملكية Visit، 200 `report:null` بعد Visit مصرح بلا تقرير، GET DRAFT/FINAL، create/update PUT strict، PLANNED/COMPLETED مسودة مسموحة، CANCELLED إنشاء/حفظ/إتمام ممنوعة مع بقاء مسودة قديمة مقروءة؛ FINAL immutable. تحقق الحد الأدنى النهائي، نقص هوية المفتش، `expectedRevision`، first-create race، تحديثان متزامنان، إتمامان متزامنان، وعدم تسرب أسماء قيود DB. إثبات AuditLog `INSPECTION_REPORT_FINALIZED` مرة واحدة وmetadata `{}` وrollback عند فشل append؛ لا audit لحفظ المسودة. إثبات بقاء لقطة Inspector/Teacher بعد تغيير الاسم، واسم المؤسسة التاريخي بعد إعادة التسمية/الأرشفة/تغيير مؤسسة Teacher؛ Visit مصدر السنة والأوقات؛ لا email/PII أو report prose في logs/audit/error/list/URL. تحقق CSRF/no-store/404 عام والغلاف الموحد.

UI/unit وconnected browser: بدء مسودة من PLANNED، حفظ صريح وإعادة فتح دون autosave، إكمال Visit ثم اعتماد التقرير، تأكيد ثبات النهائي، conflict مع تحديث يدوي بلا overwrite، مسودة CANCELLED للقراءة فقط، حقول محدودة وvalidation، نقص هوية المفتش ووصلة إكمالها، لقطة التاريخ بعد تغيير الأسماء في fixture، RTL/focus/keyboard/200% zoom/responsive؛ لا scoring أو توقيع أو طباعة. شغّل regressions G3 وG4/TASK-045 وTASK-051 وقواعد typecheck/lint/tests/build/diff-check.

TASK-030: اختبر POST عربيًا صحيحًا وإيصال `202` بالحقول المحددة فقط و`no-store`، وكل حد طول عند القيمة القصوى وفوقها (Unicode code points)، والقيم الأربع للوضعية ورفض غيرها، وقاعدة الهاتف الثابت/المحمول المحلي و`+213`، والتواريخ الصحيحة والحدود الزمنية، والفراغات ومحارف التحكم و`null` والمفاتيح المجهولة وJSON المعطوب. اختبر المؤسسات 0..5 إضافية ورفض التكرار الأساسي/الإضافي بعد التطبيع؛ UUID غير صالح/مقاطعة غير موجودة/بلا عضوية حالية دون كشف سبب `404`. تحقق أن المحاولات الصحيحة وvalidation المرفوضة تدخل حد 10/IP/15 دقيقة وأن `429` يعيد `Retry-After`، وغياب IP موثوق يفشل مغلقًا. اختبر أن كل POST صالح ينتج TeacherSubmission مستقلًا `PENDING` حتى مع إعادة الإرسال والتزامن ودون `Idempotency-Key`، ولا ينشئ Teacher أو Institution أو Assignment أو AuditLog، ولا public lookup أو PII في الرد/الأخطاء/السجلات، مع migration clean+upgrade على قاعدة معزولة.

TASK-032: اختبر أن تطابق الهاتف المعياري، والبريد وفق تطبيع النطاق دون تغيير الجزء المحلي أو aliases، والاسم الأول واللقب بعد NFC/اختزال الفراغات مع تاريخ الميلاد ينتج كلٌّ منها المرشح وسبب `SAME_PHONE/SAME_EMAIL/SAME_NAME_AND_DOB` المناسب، وأن المرشح الواحد قد يحمل أسبابًا متعددة. اختبر عدم الاكتفاء بالاسم نفسه مع DOB مختلف، أو DOB وحده، أو مكان الميلاد أو المؤسسة وحدهما؛ وعدم طيّ اختلافات الحروف العربية/التشكيل/الترقيم أو استخدام fuzzy matching، مع بقاء شخصين متشابهين مختلفين. اختبر إدراج `PENDING/INTERNAL_REVIEW` واستبعاد `REJECTED` والطلب الحالي، وعزل District وعدم اطلاع مفتش غير مصرح أو غير مصادق على الطلب أو مرشحيه. اختبر أن القائمة تعرض مؤشرًا منطقيًا فقط وأن التفصيل يعيد ملخص المرشح وأسبابه دون PII غير اللازمة، ولا يوجد public duplicate disclosure أو mutation أو persistence للمرشحين أو PII في logs/errors؛ افحص المسارات على PostgreSQL اختبار معزول مع حالات تطبيع عربية وUnicode.

TASK-033 UI/component tests: اختبر إجراءات `PENDING` و`INTERNAL_REVIEW` وفق مصفوفة ADR-026، وعدم وجود إجراءات للحالات النهائية؛ حوارات التأكيد والرجوع والإلغاء والتركيز ولوحة المفاتيح ومنع الإرسال المكرر؛ تحذير التشابه المحايد لا يعطل قرارًا صحيحًا ولا يدمج ولا يعرض confidence؛ لا حقل سبب رفض أو ملاحظة مراجعة؛ عرض آمن لـ409 والخطأ العام؛ RTL/responsive/accessibility؛ ومسار الإنتاج يبقى read-only ولا يعرض إجراءات فعالة قبل TASK-034. لا تختبر إنشاء Teacher أو DB mutation في TASK-033.

TASK-034 integration tests: فرض مصفوفة ADR-026 على الخادم؛ جسم strict و`expectedStatus` الإلزامي وسباقات `409` بلا إعادة. قبول ينشئ Teacher واحدًا ويضبط `acceptedTeacherId` كرابط FK فريد؛ تحقق من mapping كل حقول ADR-027، و`recordStatus=ACTIVE` و`archivedAt=NULL`، وأن `confirmationDate/qualifications` المحذوفتين تصبحان NULL؛ تحقق من بقاء الحقول المطلوبة في intake مُلزمة رغم nullable Teacher. `notes` وأسماء المؤسسات وreceipt/decision metadata لا تُنسخ، ولا PII uniqueness أو Teacher.notes؛ رفض/مراجعة لا ينشئان Teacher، ومراجعة داخلية فقط من PENDING، ولا Institution أو Assignment. اختبر `decidedAt/decidedByInspectorId` لكل إجراء، AuditLog واحدًا بmetadata المسموح لكل قرار وفشل append يُرجع المعاملة كلها. أرسل ACCEPT مكررًا بعد النجاح، وطلبين متزامنين: فائز واحد كحد أقصى، والخاسر `409` بلا Teacher/AuditLog إضافي ولا replay؛ لا `Idempotency-Key` مطلوب، وعميل TASK-033 لا يرسله بعد التكامل. مرشحو التشابه لا يمنعون القرار ولا يُعرض المصدر المقبول وTeacher الناتج مرتين؛ لا Teacher-comparison engine ضمن هذه المهمة. اختبر auth/CSRF/district scope، واستجابة النجاح المحدودة، وclean/upgrade migration على قاعدة اختبار معزولة. اختبر تفعيل عناصر TASK-033 فقط مع endpoint عامل.

TASK-035 API/DB tests: GET/PATCH يشترطان Inspector `ACTIVE` وعضوية حالية؛ اختبر جلسة غائبة/معطلة، عضوية منتهية/مستقبلية، و404 عام للمعرّف الغائب أو خارج النطاق وUUID مشوه. GET يعيد الحقول المحددة وتواريخ `YYYY-MM-DD` وسياق المؤسسات المعلنة من الطلب المقبول فقط، دون snapshot كامل أو notes/receipt/decision metadata أو AuditLog قراءة. تفصيل submission لا يكشف `acceptedTeacherId` خارج النطاق، ويظهر رابطًا فقط بعد قبول مرتبط. PATCH يختبر كل حقل على حدة، الجزئي والإبقاء على المحذوف، مسح nullable بـ`null`، رفض null لـ`name/surname`، رفض `""`، الجسم الفارغ/المفاتيح غير المعروفة/حقول النطاق والحالة والأرشفة والمصدر، والحدود Unicode ومحارف التحكم والتواريخ الحقيقية/المستقبلية والكرونولوجيا بعد الدمج والهاتف الجزائري والبريد والوضعيات الأربع. لا merge أو منع تحديث بسبب PII مكرر. اختبر تغير `updatedAt` عند التعديل فقط، وno-op دون AuditLog، وحدث `TEACHER_PROFILE_UPDATED` واحدًا بأسماء الحقول المتغيرة فقط دون قيم PII، وأن فشل append يرجع PATCH. يبقى submittedProfile وقرار الطلب وInstitution/Assignment وعدد Teachers دون تغيير؛ لا migration لـTASK-035. اختبر آخر كتابة ناجحة للحقل نفسه دون version precondition والحقول غير المذكورة دون فقد.

TASK-035 UI/G3: عرض/تحرير/إلغاء/حفظ مع loading/error/success وvalidation محلية/خادمية، منع double-submit، عدم التحديث المتفائل، focus/keyboard وRTL/responsive. حالات `ACTIVE/INACTIVE` بتسميات عربية read-only، والتصريحات الأصلية موسومة غير معتمدة ولا حقول تعديل لها، ولا حساب أستاذ أو قائمة/إسناد/زيارة. اختبر مسارًا متكاملًا public POST → قائمة/تفصيل المفتش وتنبيه التشابه → تأكيد ACCEPT → `acceptedTeacherId` من تفصيل مصرح → GET وواجهة Teacher → PATCH مسموح → snapshot الأصلي ثابت؛ ومساري REJECT وINTERNAL_REVIEW والسباق/الخصوصية. تظل اختبارات TASK-020..034 خضراء قبل غلق G3.

## Post-G3 workplace regression — ADR-029

تبقى اختبارات TASK-030..035 وسيناريو G3 المحفوظ دليلًا تاريخيًا لصيغة `primaryInstitutionName`/`additionalInstitutionNames`، ولا تُعاد كتابة snapshots أو migrations القديمة. من TASK-041 يُضاف مسار E2E متصل للنموذج الجديد: أربعة حقول جهة عمل مطلوبة لمؤسسة واحدة، رفض مفاتيح المؤسسات القديمة في POST الجديد، `202` بإيصال فقط، وبقاء السجل المرسل دون إنشاء Institution أو رابط. يُقرأ snapshot قديم بجميع تصريحاته الأصلية وبحقول البلدية/العنوان/هاتف المدير `null`، ويظل ACCEPT ينشئ Teacher واحدًا بلا مؤسسة معتمدة، مع بقاء قرارات G3 وملف Teacher عاملين.

TASK-040: clean+upgrade migration من checkpoint G3 على قاعدة معزولة؛ صفوف Institution القديمة تبقى سليمة والحقول الجديدة NULL، وTeacher القديم `institutionId=NULL`. اختبر FK المركب داخل District، ورفض ربط District مختلفة على مستوى DB، ورابط واحد كحد أقصى لكل Teacher، وعدم تغيير الجداول أو snapshots التاريخية.

TASK-041: تحقّق Zod وحدود النص والهاتف لكل حقل workplace، ورفض الأسماء الإضافية/المفاتيح القديمة في POST الجديد، وواجهة عربية RTL ولوحة مفاتيح/تركيز/أخطاء/إيصال. اختبر القراءة المتوافقة للقديم في تفاصيل الطلب وملف Teacher، وغياب الإنشاء/المطابقة الآلية للمؤسسة.

TASK-042: GET/PATCH مؤسسة ضمن النطاق، تحقق المدخلات والمحو الصريح بـ`null` مع بقاء الحقل المحذوف، و`409` للمؤرشفة. اختبر CSRF لـPOST القديم والجديد، وإنشاء/تعديل AuditLog ذريًّا بلا قيم هاتف/عنوان في metadata؛ لا merge على تشابه الاسم.

TASK-043/046: اختيار مؤسسة موجودة في District Teacher نفسها أو إنشاء صريح ثم ربط ذري، وفشل العملية كلها إذا فشل التدقيق أو FK. اختبر `expectedInstitutionId` وتعارض التزامن، `404` عامًا لخارج النطاق، `409` للمؤرشفة، وعدم نسخ تصريحات الأستاذ تلقائيًا إلى سجل مشترك. يُعرض «لم تُعتمد مؤسسة حالية» عند NULL؛ يفصل الملف بين التصريح التاريخي والرابط المعتمد؛ التغيير يستبدل الرابط فقط بلا تاريخ نقل أو جدول أسبوعي. أحداث التدقيق IDs وأسماء الحقول فقط بلا PII؛ تدفقات UI loading/error/success/RTL/accessibility.

TASK-047: clean+upgrade migration مع Teacher قديم بلا مؤسسة؛ جدول واحد لكل `(teacherId,academicYear)` بصيغة سنتين متتابعتين، revision افتراضي موجب، timestamps وFK/onDelete، وعدم وجود status/validFrom/validTo أو institutionId/assignmentId أو تاريخ نسخ. اختبر يوم 1..7، دقائق `0 <= start < end <= 1440`، slots متعددة/يوم، تجاور مسموح، تداخل مرفوض من DB حتى في سباق إدخال؛ اختلاف يوم/جدول لا يُرفض. اختبر حدود النصوص الاختيارية وتطبيعها في TASK-048 عند توفر API. لا API/UI/AuditLog في 047.

TASK-048: integration لauth/CSRF/district scope و404 خارج النطاق، عرض الجدول وTeacher غير المربوط، ومنع الإنشاء/التعديل دون مؤسسة حالية؛ سنة canonical/slot validation/حدود النص، تداخل برسالة آمنة، revision stale/conflict 409 بلا تغيير جزئي أو audit، وزيادة revision مرة لكل mutation ناجحة. اختبر `WEEKLY_SCHEDULE_CREATED/UPDATED` داخل transaction مع metadata IDs/counts/changedFields فقط، وعدم تسرب notes/level/group أو PII، وrollback عند فشل append. UI عربي RTL يستعرض ويحرر الجدول الحالي، loading/empty/error/conflict/keyboard/focus، ومتصفح متصل؛ بلا استثناءات أو تاريخ نسخ.

TASK-044: اختبارات API/DB تكامل وفق [عقد البحث](API_CONTRACTS.md#teacher-directory-search-task-044-contract): مصادقة ACTIVE، نطاق District الحالي (واحدة/متعددة/لا عضوية، و`404` عام لخارج النطاق)، منع تسرب cross-district في `data` و`total` و`cursor`، و`q` للاسم/اللقب والهاتف والبريد واسم المؤسسة الحالية دون التصريح التاريخي؛ اختبر تطبيع الهاتف الكامل، النص العربي الحرفي، الفراغ ورفض طول زائد. اختبر `institutionId`/غير المسندين، `professionalStatus` بما في ذلك NULL، افتراضي `recordStatus=ACTIVE` وطلب INACTIVE، وتركيب المرشحات بـAND. سنة دراسية صريحة، يوم 1..7، دقيقة بنطاق 0..1439، حدود `startMinute <= minute < endMinute`، «يعمل اليوم/الآن» بلحظة موحدة `Africa/Algiers`، جدول غائب وسنة خاطئة ورفض اجتماع بارامترات غير صالح؛ لا فحص عطلات. اختبر `limit/cursor/total/nextCursor` وترتيب surname/name/id واستقرار الصفحات مع أسماء متطابقة ورفض cursor خارج النتائج؛ رد مصغر بلا PII أو تفاصيل جدول، validation envelope وrequest ID وno-store، وعدم AuditLog للقراءة. استخدم عينة 180+ Teacher لقياس استعلامات الخادم وخطة البحث/الترقيم وتأكيد عدم N+1 أو ترقيم/ترشيح على العميل؛ لا migration/fهرس جديد دون دليل أداء.

TASK-045: 15 UI/unit tests للدليل RTL تغطي ACTIVE الافتراضي، الاستعلام الخادمي/debounce/stale response، نطاق المقاطعات، institution lookup محدود، الحالة المهنية/السجل، المؤسسة غير المعتمدة، السنة/اليوم/HH:mm→minuteOfDay/worksToday/worksNow، cursor next/previous/stale reset، empty/error/reset/navigation/projection/accessibility.
