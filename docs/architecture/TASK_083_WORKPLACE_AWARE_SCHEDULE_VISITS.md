## Current model and year label

`WeeklySchedule` is unique per `(teacherId,academicYear)` with one mutable revision. Slots currently have weekday/minutes but no Institution/date validity. The API has create schedule, add slot, partial PATCH and DELETE slot; **no collection replacement/upsert**. `Teacher.institutionId` is current home only, without transfer history. Supplementary approvals use `[validFrom,validTo)` DATE. Visit currently derives home Institution on create; RESCHEDULE changes time/year only; COMPLETE does not revalidate workplace. Its two time-only warnings are advisory and require explicit acknowledgement.

After TASK-083, `academicYear=YYYY-YYYY` remains a **logical grouping label**, not an exact school-calendar boundary. The explicit slot interval governs occurrences, including dates beyond the label's constituent years; display the actual interval, never infer September/June dates. Teacher-wide overlap protection must work across different schedule labels. Directory `worksToday/worksNow` uses the Africa/Algiers date plus weekday/minutes and dated validity; an undated legacy slot cannot prove current work or location.

## Slot schema, historical compatibility and overlap

One forward-only migration adds nullable fields to `WeeklyScheduleSlot`:

| Field | Prisma / PostgreSQL | New dated row | Existing legacy row |
|---|---|---|---|
| `institutionId` | `String? @db.Uuid` / UUID | Explicit approved Institution | NULL |
| `validFrom` | `DateTime? @db.Date` / DATE | Required, inclusive | NULL |
| `validTo` | `DateTime? @db.Date` / DATE | Optional, exclusive; NULL open end | NULL |
| `teacherId` | `String? @db.Uuid` / UUID | Server-derived parent Teacher | NULL |
| `districtId` | `String? @db.Uuid` / UUID | Server-derived Teacher district | NULL |
| `workplaceBasis` | nullable constrained string `HOME`/`SUPPLEMENTARY` | Server-derived at approval | NULL |

Teacher/District keys are justified by teacher-wide DB exclusion and composite same-district integrity. Add `WeeklySchedule(id,teacherId)` unique referenced key and composite FKs `(scheduleId,teacherId)→WeeklySchedule`, `(teacherId,districtId)→Teacher`, `(institutionId,districtId)→Institution`; RESTRICT deletes and established update conventions. Existing schedule FK stays. CHECK exactly two shapes: all six added values NULL for legacy; or Institution/start/Teacher/District/basis all non-NULL with `validTo IS NULL OR validTo > validFrom`. No defaults, backfill or rewrite. `workplaceBasis` records why a dated slot was approved; it is not HR history and is never auto-reclassified after a home change.

Replace the existing all-row slot overlap exclusion with two partial GiST exclusions using existing `btree_gist`: legacy rows keep `(scheduleId,dayOfWeek,int4range(startMinute,endMinute,'[)')) WHERE validFrom IS NULL`; dated rows enforce `(teacherId,dayOfWeek,int4range(startMinute,endMinute,'[)'),daterange(validFrom,validTo,'[)')) WHERE validFrom IS NOT NULL`. Thus time **and date** overlap reject even across different Institutions/year labels, while adjacent/disjoint historical periods coexist. Legacy-versus-dated periods are incomparable because legacy has no date; neither assume it covers all dates nor fabricate a date. Add scoped teacher/date and Institution FK indexes as needed. Keep weekday/minute CHECKs and no same-time double booking. Validate exact constraint names/SQL against migration history at implementation.

An occurrence exists at local date D/time T iff weekday matches D, `validFrom <= D`, `validTo IS NULL OR D < validTo`, and `startMinute <= T < endMinute`. A Visit crossing midnight is split into local-date segments for **advisory** schedule coverage; each segment evaluates its own dated occurrences.

## Slot workplace eligibility and writes

For a supplementary Institution B, **one** approved B relation must contain the whole slot interval: `supp.validFrom <= slot.validFrom` and (`supp.validTo IS NULL` or (`slot.validTo IS NOT NULL` and `slot.validTo <= supp.validTo`)). An open-ended slot requires open-ended supplementary approval. Adjacent separate approvals do not substitute for one containing approval; split the slot if needed. A past slot may be entered as an explicit correction when dated supplementary evidence covers it. Institution must exist, be active at new selection, and be in Teacher district.

For a new home-basis slot, Institution must equal Teacher's **current** home under the transaction lock, and `validFrom` must be today or future in Africa/Algiers. Past home cannot be reconstructed from the current FK. Current home supports future planning, not a guarantee that the Teacher remains there. Previously recorded home slots retain their Institution/basis/dates after a home change; past occurrences represent recorded schedules, not proven attendance or invented transfer history.

New schedule slots in existing create/add routes require `institutionId,validFrom`; `validTo` is optional `YYYY-MM-DD` or NULL, with strict DATE parsing and existing weekday/minute/text checks. `teacherId,districtId,workplaceBasis` are server-derived and forbidden in client body. Create with zero slots remains valid. A legacy NULL slot may remain forever. A substantive `PATCH /slots/:id` that persists a legacy slot must explicitly supply Institution and `validFrom` together, plus optional end; only that row is upgraded. A no-op PATCH does not upgrade it; DELETE of a legacy slot retains current behavior. No silent home default and no whole-collection replacement.

For a real current/future timetable change, close the old slot's interval at the effective date and create a **new slot ID** starting there. The prior period remains. Existing partial PATCH may close via `validTo` and may explicitly correct an erroneously recorded date/time/Institution, but corrections revalidate the entire resulting interval; the UI labels them as corrections and never silently overwrites elapsed history. `workplaceBasis` recalculates only for an explicit Institution correction. Revision, no-op, overlap and structural audit rules remain. Future-dated periods may coexist when their time/date applicability does not collide.

## Derived schedule consistency and UI/read model

TASK-082 workplace mutations keep their independent home/supplementary/district constraints. They must **not** reject merely because slots become inconsistent, and must not move, close or delete slots. No persisted consistency boolean and no new workplace-mutation audit metadata.

Schedule GET preserves old slot fields and adds nullable `institution:null|{id,name,municipality,archivedAt}`, `validFrom`, `validTo`, `workplaceBasis`, and `consistency:{status:'CONSISTENT'|'NEEDS_CORRECTION'|'LEGACY_UNKNOWN',reasonCode}`. Legacy all-NULL location/dates are `LEGACY_UNKNOWN` («مكان العمل غير مسجل؛ فترة السريان غير مسجلة»). Supplementary basis is `NEEDS_CORRECTION/SUPPLEMENTARY_VALIDITY_CHANGED` when no single currently approved relation contains the saved interval, even for an old period after explicit correction. Home basis with a wholly elapsed interval remains a recorded historical schedule; current home FK cannot prove/disprove its past. Home basis with an unelapsed portion and a different current home is `NEEDS_CORRECTION/HOME_CHANGED`. An archived Institution makes an unelapsed slot `NEEDS_CORRECTION/INSTITUTION_ARCHIVED`; elapsed history remains readable. A mixed past/future interval can be flagged without rewriting its past part. Otherwise status is `CONSISTENT` as an operational schedule, never proof of physical attendance. The Institution name is a **current label**, not a historical snapshot. Avoid N+1 and exclude Institution contacts, Teacher PII and audit details.

The Arabic RTL editor shows weekday/time, explicitly selected workplace, validity, existing level/group/notes, and neutral legacy/needs-correction states. Provide accessible bounded picker, close/add period and deliberate correction controls; no default home selection, final branding, invented school calendar or automatic history rewrite.

## Visit eligibility, lifecycle and warnings

New Visit create accepts explicit `institutionId` in both scheduled and retrospective bodies. Chosen Institution must be active, same district, and Teacher's eligible workplace on the **Africa/Algiers local calendar date of scheduledStartAt**, or of `actualStartAt` for retrospective EXCEPTIONAL. Eligibility uses **start date** even when Visit crosses midnight. For supplementary, its `[from,to)` contains that local date. Current home may be chosen for today/future planning. For any past-dated Visit, current home alone is not historical proof; require dated supplementary evidence at that date. Do not infer Institution from WeeklySchedule. Existing ACTIVE Teacher, owner/district/CSRF checks remain. Save selected FK and `institutionNameSnapshot`; no Visit migration or historical backfill.

`RESCHEDULE` retains `expectedRevision`, adds optional `institutionId` (omission retains stored Institution), and validates final Teacher + chosen Institution + new scheduled start date in one transaction, including date-only, Institution-only, both, and a submitted no-op. If selected Institution genuinely changes, update FK and saved name snapshot together and increment revision once. A true no-op after successful eligibility check writes/audits nothing. Recompute Institution-aware warning for final time/location. Existing PLANNED Visit later made inconsistent by workplace change remains readable, completable and cancellable. Completion uses existing state/`occurredAt` rules **without** workplace revalidation. Completed/cancelled Visit and historical snapshot never change retroactively. Any RESCHEDULE revalidates under current rules.

Workplace eligibility is a **hard** check; schedule coverage remains **advisory**. If no Teacher/year schedule exists, return `VISIT_WEEKLY_SCHEDULE_MISSING`. Otherwise `VISIT_OUTSIDE_WEEKLY_SCHEDULE` applies unless dated applicable slots at the **selected Institution** cover the full Visit interval, including both local-date segments across midnight. Slots at another Institution, legacy unknown, stale/archived Institution, wrong date or partial time do not count. Adjacent same-Institution slots may combine under ADR-031. Reuse the existing warning codes and explicit acknowledgement; a changed Institution/time/slot validity makes an old acknowledgement stale and requires recomputation. An eligible B Visit with no B coverage may proceed after acknowledgement. Warning never authorizes an ineligible workplace.

## Picker, authorization, locking and audit

Add `GET /api/v1/teachers/:teacherId/valid-workplaces?date=YYYY-MM-DD` for Visit selection. Require ACTIVE Inspector/current Teacher-district membership, strict real DATE, generic scoped 404, `Cache-Control:no-store`. Current home appears for today/future only; supplementary appears where its interval includes D. On past D, a current home with dated supplementary evidence may appear using its historical supplementary basis. Read is only a picker hint; write rechecks.

For schedule editor, a date-only query cannot prove interval containment. Extend the same scoped endpoint with a mutually exclusive interval query `validFrom=YYYY-MM-DD` and optional `validTo=YYYY-MM-DD`; omission means open end. Return only active Institutions whose home/current or one supplementary approval supports the full proposed interval, plus the basis. Strictly reject mixed `date` and interval query. The home choice requires a current/future `validFrom`. Never infer the range from academicYear. Write transaction remains authoritative.

Lock selected Institution consistently, re-read archive/district/workplace relationships in the transaction. Keep DB FK/CHECK/GiST guards and safe race mapping: malformed UUID/DATE/body 400; missing/out-of-scope 404; unavailable workplace, overlapping/stale revision or acknowledgement 409, without SQL or PII. Active Session, district membership, CSRF and request IDs remain.

Schedule create metadata `{}`; effective slot change `{changedFields:['slots'],affectedSlotIds,slotCount}`.
