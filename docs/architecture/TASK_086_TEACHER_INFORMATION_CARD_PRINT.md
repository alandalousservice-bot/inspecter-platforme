## Purpose, audience and source

The printable «بطاقة معلومات الأستاذ» is an administrative paper document for the Teacher file. The Inspector may retain it or give a paper copy to the Teacher or Institution when appropriate. Rendering remains an authenticated Inspector operation, not a public link; the document does not claim to be a national Ministry form. The screen and print use the **same TASK-084 card projection** for the same Teacher, explicit academic year and current-state read. Presentation may differ; data semantics may not. Printing later may reflect later authoritative changes. No historical card snapshot is persisted.

The authorized source is the existing `GET /api/v1/teachers/:teacherId/information-card?academicYear=YYYY-YYYY`. There is **no backend/API change**, print-data endpoint, second SQL/Prisma derivation, schema change, migration, print record, AuditLog read event, PDF service or new dependency. The print view fetches that endpoint directly, so refresh/deep links work. In particular, it must not recompute last inspection, mark, schedule consistency, qualification ordering, current workplace validity or home linkage. It must never fall back to `TeacherSubmission`: TASK-085 declared institution/email, supplementary workplaces, structured qualifications and declaration-only appointment references remain unapproved. The existing `Teacher` seed facts may print only when they are part of the authoritative TASK-084 card.

## Route, authorization and user action

- Authenticated UI route: `/app/teachers/:id/information-card/print?academicYear=YYYY-YYYY` under the current `/app` shell. Its data request uses exactly the same `:id` and explicit `academicYear` in the TASK-084 API. No public/share route or token. Add a «طباعة بطاقة المعلومات» link on the loaded screen card carrying its selected year; a Teacher profile without a selected year leads to the card's year selection, not a guessed print year.
- Open the print route in the same tab. Screen-only back control returns to `/app/teachers/:id/information-card?academicYear=...`. Opening the route does **not** call `window.print()`. An explicit keyboard-accessible «طباعة» button calls browser print only after a valid card loads. Loading, malformed/missing/repeated year, 404/out-of-scope, inactive/unauthenticated session and API errors show screen-only safe states and disable printing. No error state is formatted as a printable card.
- The API retains TASK-084 checks: ACTIVE Inspector and current membership in `Teacher.districtId`; nonexistent and out-of-scope Teacher have the same generic 404, request ID and `Cache-Control: no-store`. UI navigation adds no authorization. No district ID or private fact is placed in the URL. The year remains a canonical consecutive `YYYY-YYYY`, with no substitution on print. The view displays the API's `asOfDate` and selected `academicYear` so the current-state nature is visible.

## Print data selection

All sources below refer to fields of **the existing TASK-084 API response**. `null` is not zero or proof of absence; render «غير متوفر» unless a collection-specific message is given. Internal IDs are never printed. Names and data are current values, not historical snapshots. No additional projection field is needed.

| Birth: `birthDate`, `placeOfBirth`, `birthProvince` | `card.teacher` | YES | «غير متوفر» per value; wrap | Province is distinct from place; do not infer |
| Contact: `phone`, personal `email`, `personalAddress` | `card.teacher` | YES | Neutral per value; long address/email wrap | Authorized administrative paper; never URL/log data |
| Professional: `professionalStatus`, `professionalFramework`, `employedAt`, `confirmedAt` | `card.teacher` | YES | Existing Arabic status labels, neutral unknown; wrap framework | Distinct status values; `employedAt` is not first appointment |

The card projection intentionally omits home address/director phone and supplementary contact details, so print omits them too. Do not expand TASK-084 solely to imitate the paper source. The summary of the weekly schedule may display presence, current/legacy slot counts and correction indicator from the returned arrays, but not a new domain judgment or full slot table. A legacy unknown slot is never presented as verified current location. The independent last-inspection and mark values follow TASK-084 order/filter exactly.

## Paper and pagination

- `@page { size: A4 portrait; margin: 12mm; }`. A4 is 210 × 297 mm; the CSS page content area is **186 × 273 mm**. Keep all printed ink within it; no reliance on browser default margins or printable edge. Test with browser headers/footers disabled for the intended document. Do not inject custom page numbers or dynamic counters unless the QA proves stable.
- One page is preferred for ordinary data, never guaranteed. Natural page 2+ continuation is allowed for long Arabic text, multiple qualifications and workplaces. No global scaling to fit or font smaller than readable body text. Keep title/year/as-of and the empty physical «صورة شمسية» area together at the start when possible; use a reserved **35 × 45 mm** box. The one physical «التوقيع» area is **50 × 18 mm**, after content on the last page. Its signer is deliberately unspecified. Neither placeholder has a digital image/value. Avoid reserving an entire blank page for either.
- Print section order: header/title/year/as-of and photo box; identity/birth/contact; professional and first-appointment/installation facts; home Institution; current supplementary workplaces; structured and legacy qualifications; classification; inspection summary; weekly-distribution reference; organization; signature. A section heading stays with at least its first fact/row. Avoid splitting a compact fact, qualification or workplace row where possible; let long sections break between rows or paragraphs. No fixed-height content containers, `overflow:hidden`, absolute placement for flowing sections, text ellipsis or table clipping. Long notes are not printed.
- Set print root `lang="ar" dir="rtl"`, right-aligned Arabic labels, logical CSS spacing, semantic headings and `<dl>`/lists. Isolate email, phone, dates, time and decimal mark with `dir="ltr"`/`<bdi>` as appropriate; wrap mixed Arabic/Latin identifiers without reversing digits. Use existing system Arabic-capable font stack; print body approximately 10–11 pt, headings at least 12 pt and strong labels, with no new font dependency. If the installed font or browser breaks shaping, treat visual QA as failing rather than silently shrinking.
- Print design is ink-conscious: white background, dark text, thin grayscale rules, no dashboard cards/shadows/heavy fills; archive and schedule correction are explicit text labels, not color alone. Hide app shell/sidebar, breadcrumbs, navigation, links, controls and focus decorations in print. Screen-only print/back actions remain semantic, keyboard accessible and visibly focused on screen. A dedicated print root prevents the Inspector screen card's administrative note or other shell content from being present in the printable DOM. Hide raw URL rendering for links; no IDs, request IDs, receipt IDs, AuditLog metadata, secrets or diagnostics.

## Implementation gate and verification

TASK-086 implementation changes only the web presentation/routing, print CSS, and their tests. Reuse the existing TASK-084 client and API. No Prisma changes or DB writes, no PDF runtime and no new dependency. Use the existing Playwright development tooling for connected browser and `page.pdf()`/print-media QA where supported; this does not add runtime PDF generation. Prefer fixture schemas on the verified isolated PostgreSQL target used by project E2E; never port 5432 or production.

Tests must verify: ACTIVE/current-district access, inactive denial, generic 404 for nonexistent/out-of-scope Teachers, no public route; exact year propagation, malformed/missing year rejection and no silent default; print and screen parity for the same API projection including home/email, supplementary current/archived rows, qualifications plus separate legacy text, independent last inspection and exact mark, weekly status; declaration-only TASK-085 values absent; no administrativeNote anywhere in printable DOM, even if present in the API/screen; no IDs/receipts/audit values; null/empty cases; no DB writes/AuditLog; explicit button only after load and no auto-print; RTL, semantic labels, keyboard/focus and safe error states.

Reproducible visual QA in Chromium print media, with rendered A4 PDF or page images inspected for **minimal**, **normal**, and **stress** fixtures. Stress includes long Arabic address/framework/Institution/Inspector name, long mixed email, 3+ current supplementary rows, 5+ qualifications, long legacy text and a populated private note to prove its exclusion. Check 210 × 297 mm paper, 12 mm margins, RTL/bidi, grayscale legibility, no clipping/overlap/horizontal overflow, no accidental blank page, reasonable breaks, photo/signature dimensions and screen-only controls absent. Any failed print rendering blocks completion. A connected flow signs in → profile/card → selects year → opens print route → explicitly invokes print preview; assert the same projection and clean auth. Run TASK-084/085, TASK-080..083, G3, directory TASK-044/045, schedule TASK-047/048, Visit TASK-050/051 and report/FollowUp TASK-052/053/053A/054 regressions as affected, plus typecheck, lint, unit/integration tests, build, smoke and `git diff --check`.

Out of scope: TASK-060 and ADR-013, Inspector Visit Report printing/TASK-072, public print/share URLs, server PDF, email delivery, print-history persistence, data snapshots, automatic schedule attachment, Ministry certification, photo upload, digital signature, new organization hierarchy, TeacherSubmission fallback, new Teacher/Visit/Report derivation, and any change to TASK-085 acceptance/public intake.
