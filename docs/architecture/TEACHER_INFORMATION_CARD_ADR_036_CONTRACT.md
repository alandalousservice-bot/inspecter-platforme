# ADR-036 proposed contract — Teacher information, workplace and administrative profile evolution

Status: **ACCEPTED** after the Product Owner's final «آخر تفتيش» decision. This is the architecture contract; each proposed implementation task still requires its own precise execution/API/audit review before Luna. This contract evolves the **future** behavior of ADR-015/027/028/029/030/031 and does not rewrite their implemented history. ADR-034/035 report semantics remain unchanged. Source inventory: [field matrix](TEACHER_INFORMATION_CARD_GAP_ANALYSIS.md). No application/DB change occurs in this gate.

## Ownership and current workplace

`Teacher.institutionId` continues to be nullable, district-scoped, Inspector-approved, and unique as a **single current administrative/home institution** («المؤسسة الأم»). It is not a general many-to-many join. Teacher may also have zero or more **supplementary workplaces** («تكملة نصاب»), all in Teacher's district. They are operational links, not additional home institutions, and do not arise automatically from public declarations. No hours are inferred; the paper's label alone does not supply workload.

Smallest proposed model: `TeacherSupplementaryWorkplace(id,teacherId,institutionId,districtId,validFrom,validTo,createdAt,updatedAt)`; `districtId` is **server-derived** from Teacher, not client-controlled, and supports composite FKs `(teacherId,districtId)→Teacher(id,districtId)` and `(institutionId,districtId)→Institution(id,districtId)` with appropriate referenced unique keys. `validFrom` calendar date required, `validTo` nullable exclusive boundary, `validTo > validFrom` if present, interval `[validFrom,validTo)`. Closing a link sets `validTo`, never hard-deletes history. More than one different supplementary Institution may be valid at once; for a given Teacher/Institution, overlapping periods are forbidden, but disjoint historical rows are allowed. No uniqueness on `(teacherId,institutionId)` alone. A supplementary row cannot point to the current home Institution at creation/change; changing the home to an overlapping supplementary Institution requires explicit resolution, not automatic rewrite. FKs restrict deletion; service verifies active Institution, current Inspector district scope, and overlap atomically with appropriate row locking against concurrent home changes; DB enforces same-district and per-pair date exclusion. This is a limited workplace validity model, **not** HR transfer history; the old home relation does not gain fabricated historical dates. Home changes remain governed by existing explicit Inspector approval; historical Visits keep their snapshots.

`WeeklyScheduleSlot.institutionId` evolves to a required **value for newly created/edited slots**. Its institution must be either Teacher's home at the operation's effective time or a supplementary Institution with a valid interval then; server authorization and district checks are mandatory. Existing rows receive a **nullable** column with `NULL` retained as «historical location unknown»; no backfill from current Teacher.institutionId. The DB FK prevents dangling Institution, and the service verifies Teacher/workplace validity because the parent Teacher is indirect through WeeklySchedule. A change to home/supplementary validity does not silently rewrite slots: current schedule mutation must explicitly resolve any now-invalid location. Existing overlap GiST exclusion, single schedule per Teacher/year, revision/concurrency, and advisory schedule warnings remain. Schedule is an operational weekly pattern, not historical time-series evidence: an old slot ID is not proof of where Teacher worked on a past date. During current reads, a legacy NULL location is «غير محدد», never silently substituted with today's home. Directory works-today/now semantics continue to use day/time; institution filters/labels must not claim a legacy slot's physical location.

New Visit creation accepts an explicit Institution selected from the Teacher's home or supplementary workplaces **valid for the Visit's effective date/time** (scheduled start, or actual start for retrospective EXCEPTIONAL). The institution must be active, same district and authorized; WeeklySchedule coverage is advisory and never grants authorization. Store the chosen `institutionId` and `institutionNameSnapshot` under existing Visit contract. Existing Visits and snapshots are immutable as historical location evidence; no migration/backfill/reinterpretation. A past retrospective Visit may only select a location whose approved relationship is evidenced for that date; current home link alone is not historical proof after a home change, so unsupported past locations remain blocked pending a separate historical-location contract. Do not change old Visit report/FollowUp data.

## Teacher, Institution and employment fields

`SUBSTITUTE` is a fifth canonical Teacher/TeacherSubmission `professionalStatus` («مستخلف/مستخلفة»), **not** an alias of `TEMPORARY_CONTRACT`. The four previous values and historical rows/JSON remain untouched. Future public intake status selection/validation, Teacher PATCH/detail, directory filter, labels and tests must accept the new value; no automatic status migration. Existing public `professionalStatus` remains required.

New optional Inspector-approved Teacher master text: `professionalFramework` («الإطار»), `birthProvince` («ولاية الميلاد», distinct from `placeOfBirth`), `personalAddress` («العنوان الشخصي», private), `administrativeNote` («معلومات أخرى», Inspector-only factual administrative context, not Visit/Report/FollowUp prose). Proposed Unicode limits after NFC, trim and appropriate whitespace normalization: framework 1..120, birthProvince 1..100, personalAddress 1..300, administrativeNote 1..1000 code points when non-null; reject control chars, empty strings and overlimit input. AdministrativeNote may preserve LF but rejects other controls; it is not searchable and must not enter AuditLog prose. Absence/`null` means unknown, not a fabricated value. No professional-framework enum/reference table.

Proposed optional **current/basic facts** on Teacher, not a general event ledger: `firstEducationAppointmentDate` (`@db.Date`), `firstEducationAppointmentDecisionNumber` (text 1..120), `firstInstallationDate` (`@db.Date`), `traineeshipDate` (`@db.Date`). Existing `employedAt` stays general employment date and is **not** auto-copied into first appointment/installation; `confirmedAt` remains the already accepted confirmation/tenure date, displayed as «تاريخ الترسيم» only when verified by Inspector. Institution-specific `institutionAppointmentDate` (`@db.Date`), `institutionAppointmentNumber` (text 1..120) and `financialControllerVisaNumber` (text 1..120) are proposed as optional **current home-link facts**, editable only when the home Institution is Inspector-approved; they are cleared/explicitly re-entered when the home link changes rather than misleadingly carried to a different Institution. They do not fabricate a home-transfer ledger. If Product Owner later requires previous decisions, a new history model is needed. All these values are Inspector-entered; no public intake expansion. Dates use real `YYYY-MM-DD` dates, not timestamps or invented official numeric ranges. Decision/reference strings use NFC, trim, collapse display whitespace, reject controls and empty values, max 120 code points. Pairing date and number is not mandatory when evidence supplies only one. No fake date ordering across semantically distinct events.

Proposed coherent **current administrative classification** on Teacher: `administrativeCategory` («الصنف»), `administrativeSection` («القسم الإداري», never school class), `administrativeGrade` («الدرجة»), `administrativeClassificationEffectiveDate` (`@db.Date`). The three labels are optional normalized text 1..100 code points, no legal-range or enum invention; effective date optional, independent. Inspector-authored, current-state only, no backfilled history. Existing report snapshot strings are not master data and remain unchanged.

`Institution.email` is optional master data (not Teacher email), using existing canonical email validation/normalization: trim, maximum 254, domain lowercased, no case rewrite of local part; nullable for existing rows. Read/write only in authorized Institution detail/create/update, not public declaration by default. Directory Institution projections should remain minimal until explicitly evolved.

`TeacherQualification(id,teacherId,name,issuer,issuedAt,createdAt,updatedAt)` is the proposed child for multiple certificates: `name` required normalized 1..200; `issuer` optional normalized 1..200; `issuedAt` optional calendar date. Teacher FK restricts delete; identity is UUID, **no uniqueness on name/issuer/date** because distinct credentials may share labels and dates. Authorized Inspector can add/edit/remove an individual child under a later explicit lifecycle contract; no hard-delete policy is assumed here while ADR-014 is OPEN. `Teacher.qualifications` free text is preserved byte-for-byte for legacy records; do not parse, delete, copy or backfill child rows from it. Card shows structured rows and labels legacy text separately as «مؤهلات سابقة غير مفصلة». Public qualifications text stays optional under existing intake contract; new child records are Inspector-entered. Structured child rows require explicit API/audit rules before execution.

Marital status: `EXCLUDE_FROM_DIGITAL_MVP`; no column, API or public input. Photo: `DEFERRED`; no blob/URL/upload. Signature: `DOCUMENT_ONLY_PRESENTATION`; physical print area only. Ambiguous printed label «اللقب الفتوة»: `DEFERRED_SOURCE_LABEL_UNRESOLVED`; no field or inferred meaning. Personal address and administrative note are excluded from ordinary directory and unrelated Visit lists; authorized Teacher profile/card only. All new Teacher fields are optional to preserve existing rows; no invented defaults.

## Derived card and public boundary

Information-card mark is derived from the **latest qualifying FINAL `INSPECTOR_VISIT` V1** Report whose Visit type is `PROMOTION_EVALUATION` and whose exact-decimal `pedagogicalMark` is non-null. Order by finalization timestamp then stable report ID; if none, show unavailable, never 0 or legacy `markText`. No Teacher.mark column, scoring or automatic comparison.

«آخر تفتيش» is **derived only**, never stored on Teacher. Eligible Visits have `status=COMPLETED` and `visitType` exactly one of `TENURE_CONFIRMATION`, `PROMOTION_EVALUATION`, `MONITORING_FOLLOW_UP`, `EXCEPTIONAL`. Exclude `GUIDANCE` even when completed; it remains in general Visit history. Exclude `visitType=NULL` legacy Visits without backfill or inferred type. `PLANNED` and `CANCELLED` do not count. Use `PedagogicalVisit.occurredAt`, **not** `scheduledStartAt`; take the greatest `occurredAt`, with greatest Visit UUID as deterministic tie-break when timestamps are equal. If none qualifies, show unavailable, never a fabricated date. A completed retrospective `EXCEPTIONAL` counts without WeeklySchedule coverage. External inspections are not invented.

Proposed authenticated `GET /api/v1/teachers/:id/information-card?academicYear=YYYY-YYYY` aggregates only authorized Teacher's district-scoped profile, current home Institution, currently valid supplementary workplace rows, schedule for the explicit academic year and its slot locations (NULL = unknown), structured qualifications plus separate legacy text, District/Inspector context, derived Visit date and mark. Returns existing error envelope and `Cache-Control: no-store`; no public route, no teacher account, no write, no automatic Institution matching. Do not copy the aggregate into a giant table. The Teacher directory/list and unrelated Visit list remain minimal. UI groups identity/contact, professional and administrative facts, home/supplementary workplaces, qualifications, schedule, and read-only inspection summary. Future A4 card printing is a **different** task from Inspector Visit Report printing; photo placeholder/physical signature may appear only after print contract.

Static administrative text lives in a presentation template, not Teacher. District name and explicit academic year are current contextual sources. Directorate/inspectorate hierarchy is **not modeled authoritatively today**; card display must omit or mark unavailable dynamic organization context rather than hard-code «ولاية سطيف» or invent an organization table. No official-source claim based solely on the paper form.

Public intake classification for newly accepted/affected fields: `professionalStatus=SUBSTITUTE` = **PUBLIC_DECLARATION_REQUIRED** as one allowed choice in the already required field; existing `confirmedAt` equivalent remains **PUBLIC_DECLARATION_OPTIONAL** (`confirmationDate`); existing `qualifications` free text remains **PUBLIC_DECLARATION_OPTIONAL**. `professionalFramework`, `birthProvince`, `personalAddress`, `administrativeNote`, appointment/installation/traineeship references and dates, current classification, institution-specific appointment facts, `Institution.email`, and structured TeacherQualification rows = **INSPECTOR_ONLY** for this evolution. Home and supplementary approved links and slot location = **INSPECTOR_ONLY**, distinct from the current public workplace declaration. Last-inspection date, card mark, District/school-year/header context = **SYSTEM_DERIVED**. No new public address or administrative note input; legacy TeacherSubmission JSON and existing submissions remain untouched. The only public intake evolution **required by ADR-036** is accepting `SUBSTITUTE` in the existing required status field; it belongs to **TASK-080** together with the status's Teacher/Inspector flow, preserving body limits/privacy/rate limit and all other fields. TASK-085 is reserved for a separately approved future intake change, not a duplicate implementation of SUBSTITUTE.

## Privacy and validation boundaries

Purpose of optional master fields is Inspector administrative profile/card; source is Inspector review/entry except existing public declaration fields. Display only to an active authorized Inspector in the Teacher's current district; personal address and note never in list/search/Visit projections, logs, AuditLog metadata, or public responses. `administrativeNote` must be factual administrative context, not unrestricted sensitive case notes. Actual retention/archive/delete remains ADR-014 OPEN; no claim of indefinite retention. All new read/write contracts inherit session/CSRF, Zod validation, request ID, generic errors, district scope, safe 404, no request-body logging, no PII echo, and atomic audit with mutation using changed field **names/IDs only** after event names are approved. No new app behavior or endpoint exists merely because this document is written.

## Product decision closure

The Product Owner confirmed the four eligible types and exclusions above. The card's last-inspection Visit and its displayed pedagogical mark are **independent queries**: for example, a later completed `MONITORING_FOLLOW_UP` can supply «آخر تفتيش» while an earlier FINAL promotion V1 report supplies «النقطة /20». A later non-promotion Visit must neither clear nor fabricate the mark. No Product Owner decision remains open for this architecture contract. ADR-014 retention and ADR-017 district transfer remain separately OPEN and are not silently resolved here.
